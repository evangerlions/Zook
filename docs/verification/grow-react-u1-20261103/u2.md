# U2：AI 规划、共享行动编辑与复盘、目标续排

2026-11-03 本地候选。前端固定 `4d43e393be43c5ac3e05974047dd5e86f81143bc`，合同生成快照锚点 Zook `43bcefea2305caa867839177e6bf438062c55c77`；干净构建 `source_dirty=false`。沿用原 Web/API 进程、LightTick 身份与主数据。本次修复通用 REST 回执的资源匹配边界，没有新增业务 API 字段、数据库迁移或原生源码改动，没有上线或迁真实私人数据。

## 实现与规则

1. `/grow/planning`：选择已有目标、创建/接续会话，确认上下文和来源、澄清对话、既有队列生成草案、逐项增删改标题/投入/UTC 时间/完成标准/步骤/指导、显式确认。生成和编辑不创建 task；确认核对 session/context/plan 版本及预算。上下文编辑冻结起始版本；草案冲突保留本机，可采用云端或比较后在新版本上重新审阅，不自动改旧请求的版本。
2. `/grow/actions`：年/月/周/日及父子身份、全部公开字段编辑、重复日安排、打勾/实际计时/来源内容完成规则、最低投入、提醒延后和日历导出。内容来源必须已授权，核对既有来源回执才完成，不从计时推断学完。支持事实预览、手动复盘、复盘与已有总结历史分页。共享行动与 task、课程路线不按标题合并。
3. `/grow/goals`：暂停目标、确认持续或临时投入条件、保存/修订复盘、选择已保存复盘版本，逐项审阅未完成任务并建立手动续排草案。来源任务勾选时固定版本；来源复盘版本变化需重新选择。保存草稿不动原任务；显式确认原子替换并恢复目标，历史和谱系由原领域服务保留。恢复要求审阅全部未完成任务。

新增表单使用 origin/app/user/document 隔离的持久编辑器。正式命令发送前保存完整 method/path/body/key；丢响应、重载与 401 恢复后显式重试同一请求。已接受回执在本机保存失败时仍保留原请求；409/403/404 等保留输入，由用户核对后解除。损坏编辑器状态与跨领域路径不重放。长文本只作为数据呈现。

AI 规划遵循 `public/config.features.conversational_planning`，未开放时新增写入控件关闭，已有会话及原请求仍可核对。AI 规划使用平台既有模型路由和队列；本次没有向浏览器新增 API key 配置，也未启用历史行动总结接口的自带上游密钥模式。手动复盘不需要 AI；已有总结可读取。AI/网页关闭时，原生基础路径不依赖它们。

## 队列与兼容核对

| 领域 | 正式写入与回执 | 通用 push 与客户端路径 |
|---|---|---|
| task | 领域 REST 或 task-only push；同一意图保留原 operation ID/body/base version；REST 回执同时匹配资源类型/ID，跨资源复用 key 返回 409 | iOS `syncWireOperation`、Android `toSyncWire` 仅映射 taskCommand/TASK_COMMAND；其余由非 wire 执行器处理，不双发 |
| manual / conditions / continuation | ManualPlanningService 的 owner 锁、CAS、回执与事务；复盘/来源任务版本重检 | 原生手动队列、本次 Web durable editor；不会装入 task push |
| planning session | `planning:` 回执、context revision、草案版本、队列 run；确认才物化 task | 双端各自 PlanningStore/Controller 持久请求，本次 Web 同合同；通用 push 拒绝 |
| action workspace / review | `action:` 回执与 workspace 事务、revision；来源完成事实独立 | 双端 SharedActions 独立持久状态，本次 Web 同合同；通用 push 拒绝 |
| reflection | resource ID + base version 派生持久回执，旧 PUT header 兼容 | 保存后续排按其已审阅版本引用；不走通用 push |
| record | 已验证 record 专用 CAS/历史/回执/增量 | 沿用 U1 三端路径；通用 push 拒绝写入 |
| learning / private / bridge | 来源镜像、私人 pending 和旧来源终态回执仍属旧机制 | 已识别，不与 task 队列混发；原生化、冻结与 epoch 屏障留 U3 |

U2 未新增实体或响应字段，不要求旧 App 解析新类型；旧 action v1 写入维持升级门禁，原有 task schema 门禁保持。U0 的全领域游标晚提交/过期风险与 U3 来源权威切换并未随 U2 代签。
